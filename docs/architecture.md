# AMI・EBS・EC2・CloudFormationの関係

- **EC2**：CPU・メモリを持つ仮想サーバー。
- **EBS**：EC2に接続する永続ディスク。OS・データ・設定を保存。
- **EBSスナップショット**：ディスクのある時点のデータを保存する仕組み（メモリ上のプロセスまでは保存しない）。
- **AMI**：EC2を新規起動するためのテンプレート。EBSスナップショットへの参照などを保持。
- **CloudFormation**：宣言的なYAMLでEC2・セキュリティグループなどを作成、更新、削除する仕組み。

```text
ISUCON13 AMI
   └── 起動 → EC2 (t3.medium × 1)
                 └── EBS gp3 30GiB
CloudFormation
   ├── EC2
   └── SSH用セキュリティグループ（TCP/22, 指定IPのみ）
```

## 本番との違い

ISUCON13の競技環境はc5.largeを3台使う構成でした。ここではコストを抑えてt3.mediumを1台のみ起動します。t3.mediumはCPUバースト型のため、継続的な高負荷では本番と同様のスコアになりません。CPUクレジットをstandardにして余分なクレジット課金を避けますが、残クレジットが少ないとCPU性能が制限されます。

外部ベンチマーカー・本番用ネットワーク構成は含まれません。公式AMI内のミドルウェア、ログ、アプリ構成を調べる学習に利用します。

## 事前に確認すべきこと

- AMI `ami-041289d910c114864` が東京リージョンで現在も共有されていること。
- VPCとサブネットが同じVPCに属すること。
- パブリックサブネットのルートテーブルにインターネットゲートウェイへのルートがあること。
- SSHに使う自分のグローバルIPv4が変わっていないこと。
- ISUCON13の古い証明書やドメインには期限切れ等があり得ること。

外部からWebアプリにアクセスするポートは初期状態では公開しません。必要な場合のみ、送信元を限定した追加のルールを検討してください。
